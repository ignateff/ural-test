# Архитектура

Приложение содержит один предметный контекст — подбор детали и её складских
предложений. Он находится в `src/parts-search/`; создавать отдельные слои
для каждого поля фильтра не требуется.

- `src/app/` собирает страницу и Redux store. `store.js` читает начальное состояние
  из URL и подключает reducer; `main.jsx` подключает Bootstrap, стили и Provider.
- `parts-search/api/favoritParts.js` знает контракт поставщика: HTTP, ошибки,
  нормализацию производителей и складских предложений. Остальной код работает
  с нормализованными предложениями.
- `parts-search/model/searchSlice.js` содержит состояние, действия и async thunks.
  Создание store и singleton находятся в `app/store.js`, поэтому импорт действия
  из UI не создаёт дополнительный store. `filters.js`, `sorting.js` и `urlState.js`
  содержат соответствующие преобразования.
- При смене искомой детали модель сохраняет последний подбор и его `offersFor`
  до успешного ответа. UI показывает его с прежней подписью и фильтрами,
  временно блокируя взаимодействие и прокрутку документа на время загрузки.
- `parts-search/ui/search/` управляет вводом и отложенными запросами производителей.
- `parts-search/ui/offers/` применяет фильтрацию и сортировку, строит шапку и таблицу.
  `useOffersWindow.js` относится только к таблице и расположен рядом с ней.
- `parts-search/ui/filters/OfferFiltersDialog.jsx` управляет нативным модальным
  окном, фокусом и блокировкой фона. `OffersHeader.jsx` отвечает за строку управления
  и открытие окна; дропдауны и выбранные теги находятся рядом с группами фильтров.
- `parts-search/ui/feedback/` содержит повторно используемые сообщения загрузки,
  ошибки и статуса.

Направление зависимостей: `app → parts-search/ui → model → api`.
UI может использовать API только через модель; модель и API не импортируют UI
или `app`. Общий state подбора сохраняет существующий ключ Redux `search`.
Импорты указывают на нужный файл напрямую; промежуточные re-export-файлы не нужны.

Палитра и цветовые переменные — `app/theme.css`, стили оболочки — `app/styles.css`. Стили поиска, предложений и фильтров находятся
в соответствующих UI-каталогах; `parts-search/styles.css` задаёт порядок их загрузки.
Базовые и мобильные правила одной области находятся в одном файле. Нюансы
нативного dialog, закреплённых заголовков и виртуализации сохраняются вместе
с кодом, который ими управляет.

Vitest-тесты сгруппированы по областям в `test/`, браузерные — в `e2e/`.
Интеграционные проверки проходят через настоящее приложение с подменой HTTP,
а геометрия и браузерное поведение проверяются Playwright.
