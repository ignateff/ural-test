# Подбор автозапчастей

SPA для тестового задания: React, Redux Toolkit, JavaScript, Bootstrap и Vite. Без TypeScript, серверного приложения, прокси и серверных функций. Браузер обращается напрямую к HTTPS API Favorit Parts, который разрешает CORS (`Access-Control-Allow-Origin: *`).

## Локальный запуск

Требуется Node.js 22.13+ (проверено на Node.js 24).

```sh
npm ci
npm run dev
```

Откройте адрес из терминала, обычно http://localhost:5173.

Публичный ключ из примеров документации используется по умолчанию. Примеры артикулов: `01089`, `7160500039S`. Для `01089` можно выбрать `ASAM` или `FEBI`. Доступность и лимиты примерного ключа зависят от поставщика.

Необязательно: скопируйте `.env.example` в `.env` и задайте `VITE_FAVORIT_API_KEY`. Ключ в SPA доступен посетителю через клиентскую сборку и сетевые запросы; переменная окружения не делает его секретным.

## Проверки и сборка

```sh
npm test
npm run test:a11y
npm run build
npm run preview
```

`npm run build` создаёт статические файлы в `dist/`. Их можно разместить на статическом HTTPS-хостинге. `npm run preview` служит только для локального просмотра сборки.

## Поиск

1. После паузы ввода в 500 мс отправляется запрос с номером детали; из ответа извлекаются уникальные бренды.
2. Выбор бренда отправляет запрос с номером, брендом и `analogues=on`. Искомые детали и вложенные аналоги отображаются в общей таблице.
3. Каждая строка соответствует складу: цена из `warehouses[].price`, остаток из `warehouses[].stock`. Если складов нет, показываются отсутствие наличия и прочерк вместо цены. Устаревшее поле `goods[].price` не используется.

Есть загрузка, сообщения об ошибках, повтор запроса, пустые результаты, отсутствие остатков, таймаут 20 секунд, отмена запросов и защита от запоздалых ответов при смене номера/бренда. Пустая структура в `goods` исключается из результатов. Спецсимволы кодируются через `URLSearchParams`.

### Ссылка на подбор

Текущий артикул и производитель хранятся в адресе страницы (`?number=01089&brand=ASAM`): ссылку можно сохранить или отправить, при открытии подбор восстанавливается и предложения загружаются сразу. Адрес обновляется через `history.replaceState`, поэтому новых записей в истории браузера не появляется; при очистке поля параметры удаляются, а прочие параметры и хэш не теряются (значения нормализуются `URLSearchParams`). Производитель из ссылки сохраняется, даже если поставщик сейчас не вернул его в списке: он остаётся выбранным и участвует в запросе предложений. Значения санитизируются: пробелы обрезаются, артикул ограничен длиной поля ввода, производитель — 200 символами; производитель без артикула отбрасывается.

## Структура

- `src/App.jsx` — компоновка страницы.
- `src/components/` — шапка, компактная закреплённая панель поиска, адаптивная таблица, объявление статуса, загрузка и ошибка.
- `src/store.js` — Redux и асинхронные действия; начальный подбор читается из адреса.
- `src/urlState.js` — чтение, сборка и запись подбора в адрес страницы.
- `src/useSearchUrlSync.js` — синхронизация текущего подбора с адресом.
- `src/api.js` — прямые запросы к Favorit Parts, обработка ошибок и преобразование ответа.
- `src/styles.css` — стили поверх Bootstrap.
- `test/search.test.js` — проверки контракта API и гонок запросов.
- `test/accessibility.test.jsx` — axe-core, доступные имена, сообщения о загрузке и ошибках, управление поиском с клавиатуры, сохранение фокуса после очистки, плотная таблица складских строк.
- `test/offers-presentation.test.jsx` — единое представление результата и существенные поля складских строк.
- `test/url-state.test.js` — чтение и сборка адреса подбора, запись с внедряемыми `history`/`location`.
- `test/url-state.test.jsx` — восстановление подбора из ссылки и обновление адреса через интерфейс.
- `test/app-test-helpers.jsx` — общие помощники интеграционных проверок: настоящие React и Redux, подмена только `fetch`, аудит axe.
- `test/setup.js` — подключение jest-dom и заглушки `ResizeObserver` для JSDOM.

## Доступность

Есть ссылка перехода к основному содержимому, подпись и подсказка поля, подписанный нативный список производителей, заголовки и название таблицы. Результаты поиска объявляются через короткие сообщения `role="status"`; ошибки — через `role="alert"`. Таблица не включена в live region, чтобы скринридер не зачитывал сотни строк при загрузке. Для уменьшенного движения анимация загрузки отключается.

Автоматические проверки используют React Testing Library, user-event, axe-core и JSDOM. Сетевые ответы подменяются на уровне `fetch`, остальная цепочка React → Redux → API остаётся настоящей. Проверяются стартовый экран, производители, предложения, загрузка, ошибки и пустые результаты. Аудит axe не заменяет ручную проверку скринридером. JSDOM не рассчитывает визуальный контраст и геометрию: правило `color-contrast` отключено явно; контраст, видимость фокуса и адаптивную вёрстку нужно проверять в браузере.

Документация: https://lk.favorit-parts.ru/static/wsprice.pdf (06.03.2023).

## Компактный подбор

Артикул и производитель размещены в закреплённой панели. Заголовки таблицы закрепляются под ней с учётом фактической высоты панели (она измеряется до первой отрисовки и обновляется `ResizeObserver`); на экранах до 575px та же таблица отображается карточками с подписями склада, цены и остатка — без второго, скрытого представления. Прокрутка остаётся общей для документа. Смена подбора возвращает к началу результатов и сохраняет фокус в поле или списке; очистка возвращает фокус в поле артикула. Строки стали плотнее (метка искомой детали или аналога перенесена в строку производителя и артикула), длинные значения переносятся без наложений, вторичный текст имеет контраст не ниже 4.5:1, а фокус клавиатуры виден как спокойный контур 2px приглушённого зелёного — одинаковый у полей, селектора, кнопок и ссылок (5.15:1 на белом, не ниже 3:1 на остальных фонах панели). Собственные синие и красные ореолы Bootstrap у селектора и кнопок при фокусе убраны, кнопки сохраняют свои базовые цвета.

Финальная проверка 23.10.2026 на интегрированной ветке: в браузере (Chrome 154 headless) на подготовленных 160 деталях / 321 складской строке проверены первый экран и глубокая прокрутка 8000 px, совпадение низа закреплённой панели и верха заголовков (0px зазора и перекрытия, в том числе при высоте панели 116.5 → 134.5 px), одна прокрутка документа, смена производителя с клавиатуры из нижней части списка с сохранением фокуса и показом начала результатов, длинные значения, контраст и заметный фокус; на 320×568 и 390×820 px — карточки без горизонтальной прокрутки, неразрывные подписи данных, закреплённая панель, увеличение текста (320 px ≈ 200 % масштаба страницы), состояния загрузки, ошибки, пустого результата, повтора и очистки. Поле артикула, кнопка очистки и селектор производителя выровнены по высоте (42 px; 66 px при увеличении текста до 200 %) в любом состоянии селектора — при загрузке, после загрузки, с выбранным и с длинным названием производителя, при ошибке и пустом списке; проверено на 900/1000/1083/1280 px, на 320/390 px высота обоих элементов также совпадает. Автоматические проверки (`npm test` 32/32, `npm run test:a11y` 16/16) и `npm run build` проходят. JSDOM не применяет медиазапросы и не рассчитывает контраст: геометрия и визуальный контраст подтверждены браузерной проверкой, а не автоматическими тестами.

Длинный список (более 100 складских предложений после фильтрации) виртуализируется:
в документе остаётся видимое окно с запасом, а обычная прокрутка страницы
достигает всех строк без пагинации. Высота строк измеряется по содержимому,
включая карточки на телефоне. Счётчик и доступные индексы относятся ко всему
отфильтрованному списку. Встроенный поиск браузера по странице и печать видят
только отрисованное окно; при 100 строках и меньше список отрисован полностью.

## Фильтры и сортировка складских предложений

Фильтры применяются сразу к полному загруженному подбору, без дополнительных
запросов к поставщику. Доступны наличие (остаток больше нуля), несколько складов,
несколько производителей строк, тип строки (искомая деталь / аналоги) и цена
«от–до» с копейками. Между группами действует И, внутри выбора складов и
производителей — ИЛИ. Границы цены включительные; пустая граница не ограничивает
диапазон, обратный диапазон даёт пустой результат. Деталь без складских
предложений считается отсутствующей в наличии и исключается при активном
ценовом фильтре.

При активных фильтрах счётчик показывает «Показано N из M»; пустой результат
предлагает сбросить фильтры. Сброс сохраняет сортировку. Новый артикул или
производитель искомой детали очищает фильтры, сохраняя выбранный порядок.
Сортировка по цене, остатку, производителю строки и складу устойчива: равные
значения сохраняют порядок поставщика, предложения без цены идут в конце при
любом направлении сортировки по цене. По умолчанию действует порядок поставщика.
Заголовок колонки переключает возрастание → убывание → порядок поставщика;
состояние доступно через `aria-sort`, изменения объявляются коротким статусом.

До 575px фильтры свёрнуты, в том числе при открытии ссылки: кнопка «Фильтры (N)»
показывает число активных **групп**, раскрывает единственную панель в потоке
страницы и доступна с клавиатуры. Сортировка рядом доступна без раскрытия.
Начиная с 576px фильтры всегда видимы над таблицей. Прокрутка остаётся общей
для документа; заголовки таблицы закреплены под панелью поиска.

Все параметры сохраняются заменой текущего адреса без новых записей истории;
перезагрузка и ссылка восстанавливают подбор. Значения по умолчанию и невалидные
значения удаляются, посторонние параметры и хэш сохраняются.

| Параметр | Значения |
| --- | --- |
| `number` | Артикул искомой детали |
| `brand` | Производитель **искомой детали** |
| `sort`, `order` | `price` / `stock` / `brand` / `warehouse`; направление `asc` / `desc` (оба параметра обязательны для сортировки) |
| `stock` | `in` / `out`; отсутствие — все строки |
| `wh` | Название склада; параметр повторяется для нескольких складов |
| `brands` | Производитель **строки**; параметр повторяется для нескольких производителей |
| `kind` | `original` / `analogue`; отсутствие — все строки |
| `priceFrom`, `priceTo` | Конечные десятичные числа с точкой; пустая граница отсутствует |

Список проходит через фильтрацию, затем сортировку, затем виртуализацию.
При более 100 строках отображается измеряемое окно с запасом; короткие и
отфильтрованные до 100 строк результаты полностью находятся в DOM. Счётчик
относится ко всему результату, `aria-rowcount` включает заголовок таблицы,
`aria-rowindex` указывает позицию строки в полном упорядоченном наборе.
Встроенный поиск браузера и печать видят только отрисованное окно длинного
списка; обычная прокрутка достигает всех предложений. Изменение фильтра,
сортировки или подбора возвращает представление к началу результатов,
сохраняя фокус управляющего элемента.
